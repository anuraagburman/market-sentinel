# T-006 — Deterministic portfolio valuation

- **Implementer:** Codex   **Reviewer:** Claude Code
- **Branch:** task/T-006-valuation   **Depends on:** T-005 (merged), ADR-002   **Contract version:** v1
- **Effort:** default (high for price selection and the unavailable-value rules in `domain/valuation.py`)

## Problem
The Today page shows exposure as `{kind: "calculation"}` or `{kind: "unavailable", reason}`, but
nothing computes it. Valuation is the arithmetic every brief depends on. If it quietly treats a missing
price as zero, uses a close from after the cutoff, or picks one of two conflicting prices, every
downstream judgment inherits a wrong number that looks right.

## User-visible outcome
For a confirmed portfolio version and a cutoff, the API returns each position's price (with its
source observation), market value, unrealized P/L and weight, plus totals and a coverage count.
Anything that cannot be computed is `unavailable` with a reason code. It is never zero and never
left out without a count.

## Inputs
- **PortfolioVersion + positions** from a `PortfolioRepository` protocol. The file-backed default reads
  `evals/fixtures/portfolio/portfolio_version.json` and `positions.json`. It is synthetic and temporary
  until confirm/persistence exists (proposed T-011). The loader validates on startup and fails fast on:
  a position whose `portfolio_version_id` is unknown, two positions for the same
  (`portfolio_version_id`, `instrument_id`), non-positive quantity.
- **Observations** from an `ObservationRepository` protocol; the default reads
  `evals/fixtures/portfolio/observations.json` (fails fast on duplicate ids).
- **Cutoff:** a UTC `Z` datetime supplied by the caller. Valuation never reads the wall clock.

Tests inject their own repositories.

## Rules (in `domain/valuation.py`, pure: no I/O, no clock, `Decimal` only, never `float`)

### Price selection, per position
Eligible observations for the position's `instrument_id`: `metric == "close"`, `session` in
`regular | half_day`, `adjustment == "none"`, **`observed_at <= cutoff` and `received_at <= cutoff`**.
Take those with the latest `observed_at`:
- none → price `null`, market value unavailable `no_price`
- more than one **with different values** → price `null`, unavailable `conflicting_prices`
  (never pick one); identical values → use the one with the smallest `id`
- chosen observation `unit` ≠ position `currency` → unavailable `unit_mismatch`

Checked **before** price selection: position `currency` ≠ `"USD"` → unavailable
`currency_out_of_scope` (ADR-002 §4), with price `null`.

Staleness is not judged here (ADR-002 §5); each price carries its `observed_at` so policy can decide.

### Amounts
`Amount = {kind: "calculation", value: decimal-string, basis: str} | {kind: "unavailable", reason: code}`,
the same shape as `Exposure` in `apps/web/lib/today/types.ts`.

| Field | Calculation when | Otherwise (reason) |
|---|---|---|
| `market_value` | price chosen | rules above |
| `unrealized_pl` = market_value − cost_basis | market value available and `cost_basis` not null | `market_value_unavailable`, else `cost_basis_unknown` |
| `weight` = market_value / priced_value | market value available and priced_value > 0 | `market_value_unavailable`, else `no_priced_value` |
| `totals.priced_value` = Σ available market values | ≥ 1 priced position | `no_priced_value` |
| `totals.cash` | `cash` present and USD | absent → `cash_unknown`; non-USD → `currency_out_of_scope` |
| `totals.total_value` = priced_value + cash | every position priced **and** cash available | first applicable of `positions_unpriced`, `cash_unknown`, `currency_out_of_scope` |

`basis` strings are fixed text, e.g. `"quantity × close"`, `"share of priced value (excludes cash and unpriced positions)"`.

### Precision
Compute exactly in a local `Decimal` context (prec 34). Quantize only in the response model: money to
`0.01`, weights to `0.000001`, both `ROUND_HALF_EVEN`, serialized as fixed-point decimal strings (no
exponent). `priced_value` is the quantized exact sum, not a sum of quantized values; the basis text says so.

## Endpoint
**`GET /portfolio-versions/{id}/valuation?cutoff=2026-09-25T21:00:00Z`** → `200`:
```
{
  portfolio_version_id, base_currency: "USD", cutoff,
  positions: [{                       # in the repository's position order
    instrument_id, display_symbol, quantity, cost_basis,  # echoed as stored; null stays null
    price: {value, observation_id, observed_at, feed} | null,
    market_value: Amount, unrealized_pl: Amount, weight: Amount
  }],
  totals: {priced_value: Amount, cash: Amount, total_value: Amount},
  coverage: {positions: int, priced: int, unpriced: int, by_reason: {code: int}}  # market_value reasons
}
```
Errors (problem body, like the imports routes): unknown version → `404 portfolio_version_not_found`;
status `preview` → `409 portfolio_version_not_confirmed`; `base_currency` ≠ USD →
`422 base_currency_out_of_scope`; `cutoff` missing, not UTC `Z`, or not a real datetime → `422 invalid_request`;
`cutoff` earlier than `confirmed_at` → `422 cutoff_before_confirmation` (the version didn't exist yet).

## Acceptance (fixture portfolio, cutoff `2026-09-25T21:00:00Z`)
Numbers computed from the frozen fixtures with Python `Decimal`:
- 19 positions; `coverage` = `{positions: 19, priced: 18, unpriced: 1, by_reason: {no_price: 1}}`.
- `totals.priced_value` = `12812.83`; `totals.cash` unavailable `cash_unknown`; `totals.total_value`
  unavailable `positions_unpriced`.
- SYN01: price `625.50`, market value `6255.00`, P/L `455.00`, weight `0.488183` (the >20% concentration case).
- SYN02: quantity `2.5` × `50.00` → `125.00`, P/L `15.00`, weight `0.009756`.
- SYN03: price `null`; market value, P/L and weight unavailable (`no_price`, `market_value_unavailable` ×2).
- SYN04: market value `216.18`; P/L unavailable `cost_basis_unknown`; weight `0.016872`.
- SYN05: `139.75`, P/L `19.75`, weight `0.010907`. It is valued even though it closes below $5 (ADR-002 §2).
- SYN19: `412.65`, P/L `122.65`, weight `0.032206`.

Injected-repository cases (built in tests, not committed):
- A close with `received_at` after the cutoff is ignored, and an earlier eligible close is used instead.
  If none exists → `no_price`. The same applies to `observed_at` after the cutoff.
- `pre`/`post` sessions, `last_price`, and `split_adjusted` closes are never used; `half_day` is.
- Two closes at the same latest `observed_at` with different values → `conflicting_prices`; same value → smallest `id`.
- A CAD position (e.g. Synthela 21's id) → `currency_out_of_scope`, excluded from totals, counted in coverage.
- A USD position whose close has unit `CAD` → `unit_mismatch`.
- Cash `{amount: "1000.00", currency: "USD"}` with every position priced → `total_value` = priced_value + 1000.00.
- All positions unpriced → `priced_value` and every weight unavailable `no_priced_value` / `market_value_unavailable`.
- Properties: permuting positions or observations never changes any value (only position order follows
  the repository); scaling one quantity by k scales its exact market value by k; the exact priced
  value equals the exact sum of available market values.
- Endpoint: every error case above; loader rejects each bad-fixture case.
