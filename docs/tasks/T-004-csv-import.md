## Problem
Users start by importing holdings from a CSV. Nothing accepts or checks a file yet, and a silent
mistake here (a float rounding, a dropped duplicate, a blank cost basis read as zero, a formula cell)
would poison every later number.

## User-visible outcome
`POST /imports` accepts a CSV and returns a row-by-row preview; `GET /imports/{id}` returns it again.
Every problem row is listed with a code and a plain message. Nothing is silently fixed or aggregated.

## Inputs / outputs
**`POST /imports`**: multipart file upload. Returns `201` with the preview (validation is synchronous
at these limits; the async job in the architecture doc comes with persistence later).
**`GET /imports/{id}`**: the same preview, or `404`.

Preview: `id`, `file_sha256`, `received_at` (UTC `Z`), `columns` (detected → mapped, plus `unknown`),
`rows[]`, `summary` (counts by status and by code). Each row has: `row_number` (1-based, header
excluded), `raw` (original cell strings), `parsed` (`symbol`, `quantity`, `cost_basis`, `currency`,
with decimals as strings), `status` (`ok | warning | error`), `issues[]` (`code`, `field`, `message`),
and `resolution: "pending"`. Symbol resolution is T-005.

Columns: `symbol`, `quantity`, `currency` required; `cost_basis` optional. Header matching trims and
ignores case. Unknown columns are reported, not rejected.

Row issue codes (at minimum):
| Code | Status | Rule |
|---|---|---|
| `blank_row` | warning | A blank CSV record (no cells) stays visible with null parsed fields and this single issue; it counts toward the row limit. Delimited empty cells still receive field validation. |
| `duplicate_row` | warning | Same symbol+quantity+cost_basis+currency as an earlier row; cite that row. Not merged. |
| `missing_cost_basis` | warning | Empty `cost_basis` → `null`, message says "unavailable", never `0`. |
| `missing_symbol` | error | Empty symbol. |
| `invalid_decimal` | error | Not a plain decimal. `1,000`, `1e3`, `NaN`, and currency symbols are rejected, not guessed. |
| `non_positive_quantity` | error | Zero or negative. Shorts are flagged, not transformed. |
| `invalid_currency` | error | Not three uppercase letters. |
| `formula_like_value` | error | A cell starting with `=`, `+`, `@`, a tab, or CR, or with `-` that isn't a valid negative number. |

File-level rejections (no preview): > 1 MB → `413`; not UTF-8 (a BOM is allowed) → `422`; > 1,000 data
rows → `422`; wrong content type → `415`; missing required column → `422` naming it.

## Invariants
- Parse as data only: `csv` module, all cells as strings, `Decimal` for numbers, never `float`.
- Missing is `null`, never `0`. Nothing is dropped, merged, or reordered.
- Deterministic: same bytes → same preview (apart from `id` and `received_at`).
- Store previews in a process-local in-memory repository behind a small interface, documented as
  temporary; persistence and `confirm` come in a later task. No migrations here.
- No auth yet; use no tenant field. Tests make no network calls.

## Error states
File-level errors return a problem body (`code`, `message`) and never a partial preview.
