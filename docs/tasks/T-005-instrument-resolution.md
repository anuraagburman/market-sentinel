# T-005 — Instrument resolution

- **Implementer:** Codex   **Reviewer:** Claude Code

- **Effort:** default (high for the effective-date rules in `domain/instruments.py`)

## Problem
T-004 previews every row with `resolution: "pending"`. Positions need a stable `instrument_id`, and
tickers are only labels: they get reused, renamed, and shared across share classes. A resolver that
guesses (fuzzy match, first hit, "current" symbol regardless of date) would attach a holding to the
wrong company without anyone noticing.

## User-visible outcome
Each preview row shows which instrument it matched, why, or why it didn't: resolved, ambiguous (with
candidates), unresolved (with a reason code), or not attempted. The user can look up an instrument by
exact symbol and select it for a row, or clear that choice. Nothing is auto-picked when there is doubt.

## Inputs / outputs

### Instrument master (synthetic, generated)
`generate.py` also writes `evals/fixtures/instruments/instruments.json` and `symbol_mappings.json`.
Every existing fixture file must regenerate byte-identical.

- Instrument: `id` (UUID), `name`, `asset_type` (`common_stock | preferred_stock`), `currency`.
- Symbol mapping: `symbol`, `instrument_id`, `valid_from` (date, inclusive), `valid_to` (date,
  exclusive, `null` = open). One instrument never has two overlapping mappings. Overlapping mappings
  of one symbol to different instruments are allowed; that is what "ambiguous" means.

Contents:
| Issuer | Instrument | Mappings | Case it covers |
|---|---|---|---|
| 01–19 | Synthela NN, common, USD, id `uid(NN)` (matches `positions.json`) | `SYNNN` from 2020-01-01, open | normal |
| 02 | Synthela 02 Preferred, preferred, USD, new id | `SYN02P` from 2020-01-01, open | share class |
| 02 | both Synthela 02 instruments | `SYN-AMB` from 2020-01-01, open, to each | ambiguous |
| 20 | Synthela 20, common, USD | `SYN-OLD20` 2020-01-01 → 2026-06-01; `SYN20` from 2026-06-01 | ticker change |
| 21 | Synthela 21, common, **CAD** | `SYN-RE` 2020-01-01 → 2026-07-01; `SYN21` from 2026-07-01 | currency mismatch |
| 22 | Synthela 22, common, USD | `SYN-RE` from 2026-07-01 | symbol reuse |

New ids stay outside every id `generate.py` already emits; a fixture test asserts id uniqueness
across all generated files. `SYN-TYPO` has no mapping.

The loader validates on startup and fails fast on duplicate ids, `valid_to <= valid_from`, a mapping
to an unknown instrument, or overlapping mappings for one instrument. The app reads the master
through an `InstrumentRepository` protocol; the file-backed default is documented as synthetic and
temporary until provider reference data (T-008). Tests inject their own repository.

### Resolution (per row, replaces `resolution: "pending"`)
```
resolution: {
  status: "resolved" | "ambiguous" | "unresolved" | "not_attempted",
  method: "exact_symbol" | "user_selected" | null,
  instrument_id: UUID | null,
  display_symbol: str | null,     # the instrument's symbol on as_of
  candidates: [{instrument_id, display_symbol, name, asset_type}],  # sorted by instrument_id
  issues: [{code, field, message}],
  as_of: date,
  selected_at: datetime | null    # UTC Z; set only for user_selected
}
```
`as_of` is the UTC date of `received_at`. `create_preview` takes an injectable clock so tests fix it.
Matching trims and ASCII-uppercases the parsed symbol, then does an **exact** lookup of mappings
active on `as_of`. No punctuation rewriting (`BRK.B` ≠ `BRK-B`) and no fuzzy matching.

| Situation | status | issues (code, severity in message) | candidates |
|---|---|---|---|
| One active mapping | `resolved`, `exact_symbol` | — | [] |
| Resolved, instrument currency ≠ row currency | `resolved` | `currency_mismatch` (warning; nothing converted) | [] |
| Resolved, symbol mapped to a different instrument before `as_of` | `resolved` | `symbol_reassigned` (warning; names the earlier instrument) | [] |
| More than one active mapping | `ambiguous` | `symbol_ambiguous` | all active matches |
| No active mapping, but an earlier one ended before `as_of` | `unresolved` | `symbol_retired` (names the instrument's current symbol) | that instrument |
| No mapping ever | `unresolved` | `symbol_not_found` | [] |
| `parsed.symbol` null, or the symbol cell is `formula_like_value` | `not_attempted` | — | [] |

Resolution runs on every row with a usable symbol, even if other fields have errors. Row `status`
remains validation-only; `summary` gains `by_resolution` (counts by resolution status).

### Endpoints
- **`GET /instruments?symbol=X&as_of=YYYY-MM-DD`** — exact, case-insensitive; `as_of` defaults to
  today UTC. Returns matching instruments with their mapping. No results → `200` with `[]`.
  Missing `symbol` → `422` problem body.
- **`PUT /imports/{id}/rows/{row_number}/resolution`** — body `{"instrument_id": UUID}`. Sets
  `status: resolved`, `method: user_selected`, `selected_at`, `display_symbol` (on the preview's
  `as_of`), and recomputes `currency_mismatch` for the chosen instrument. Automatic issues and
  candidates stay visible for audit. The instrument need not be among the candidates (typo fixes).
  Returns `200` with the row. Repeating the same selection is idempotent apart from `selected_at`.
- **`DELETE` same path** — restores the automatic result; `200` with the row.
- Errors (problem body): unknown import or row → `404`; unknown instrument → `422 unknown_instrument`;
  instrument with no mapping active on `as_of` → `422 instrument_not_listed`; a `blank_row` row →
  `409 row_not_resolvable`.
- `GET /imports/{id}` reflects selections. `raw` and `parsed` never change.

## Invariants
- Identity is `instrument_id`. A symbol is a label looked up on a date, never a key.
- Never auto-pick between candidates, never follow a ticker change silently, never infer a symbol
  from a typo. Doubt becomes `ambiguous` or `unresolved` with a code.
- Never convert or "fix" currency; flag mismatches.
- Deterministic: same bytes + same `as_of` + same master → same resolutions.
- No network calls; no model calls. Missing stays `null`.

## Error states
- Master fails validation → app startup fails with a message naming the bad record (never a partial
  master).
- Unresolved and ambiguous rows are normal preview states, not HTTP errors.
